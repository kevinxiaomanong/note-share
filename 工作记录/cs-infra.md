### **存储体系**

对于存储器 它的速度越快、能耗会越高、而且材料成本也越贵，以至于速度快的存储器容量都比较小

CPU并不会直接和每一种存储器设备直接打交道，每一种存储器设备只和相邻的存储器打交道，访问的逻辑是CPU需要访问内存某个数据，次序是寄存器-->L1/L2/L3 -->内存



可以分为以下几个级别：

1. CPU 寄存器、L1 L2 L3 Cache缓存
2. 内存
3. SSD/HHD 硬盘

寄存器，一般要求在半个CPU时钟周期内完成读写，例如2 GHZ主频的CPU 时钟周期就是0.5ns

CPU Cache是静态随机存储器芯片，高速缓存可以分为L1/L2/L3 三层高速缓存，只要有电数据就可以保持存在

每个CPU核心都有一块属于自己的L1高速缓存，指令和数据分开存放，L2也是共有，而L3最大是多个CPU核心共有

内存：是动态随机存取芯片，数据存储在电容里，电容会不断漏电，需要定时刷新电容，所以称为动态存储器

SSD固态硬盘，HHD机械硬盘，已经主键被SSD替代了，断电后数据还存在

CPU如何选择线程？

在Linux内核中进程和线程都用task_struct结构体表示，区别在于线程的task_struct结构体里部分资源是共享了进程已创建的资源，比如内存地址空间、FD、代码段等，所以线程被称为轻量级线程，其承载的资源较少

### **中断**

中断是CPU暂停当前执行的程序，转去处理更紧急事件的机制，处理完后再返回原程序继续执行

正常执行程序-->突发事件（网络包到达、除零错误、键盘按键）-->保存现场、跳转处理、恢复现场-->继续原程序



硬件中断（异步）

由外部硬件设备触发，与CPU当前执行无关，例如时钟芯片每10ms触发一次驱动进程调度，磁盘控制器的IO读写完成，网卡数据包到达，如果没有时钟中断，用户程序将永远占用CPU，OS无法夺回控制权

软件中断/异常（同步）

由CPU执行指令时自身触发，如系统调用、缺页异常，用户程序需要请求内核服务（读文件、建socket等）用软中断触发



1. 中断信号到达CPU
2. CPU完成当前指令，保存现场
3. 切换内核态，执行响应中断处理程序
4. 恢复现场，返回原程序



中断上半部/下半部

硬件中断处理时，中断是关闭的，所以要尽快完成

下半部可以稍后再安全时机执行



总结：中断是硬件与软件沟通的桥梁，也是操作系统掌握CPU的根本手段，没有中断就没有多任务、没有IO、没有系统调用







**内核**

内核是操作系统的核心程序，常驻内存，直接管理硬件资源，是用户程序与硬件之间的唯一中间层

1、进程管理

- 创建/销毁进程和线程
- CPU调度
- IPC进程间通信（管道、信号、共享内存）
- 进程隔离

2、内存管理

- 虚拟内存：给每个进程独立的地址空间
- 物理内存分配与回收
- 缺页处理、内存换页

3、文件系统

- 抽象磁盘为文件/目录树
- 支持多种文件系统
- 权限控制、page cache

4、设备驱动

统一抽象各种硬件设备，用户程序用同一套接口read/write操作磁盘、网卡，一切皆文件



内核态可以访问全部物理内存，以及全部指令

内核架构分为宏内核，即所有核心功能都运行在内核态，跑在同一个地址空间

微内核：只保留最小功能（IPC/基本内存管理、进程调度）其余服务跑在用户态



大多数OS将内存分成两个区域：内核空间（只有内核程序可以访问）&用户空间

用户空间的代码只能访问局部的内存空间，当程序使用用户空间时我们常说程序在用户态执行，使用内核空间时则在内核态执行，应用程序如果需要进入内核空间要通过系统调用



**内存管理&分配**

先把条件固定：

- 32 位虚拟地址：总空间 232=4GB

- 页面大小 4KB=212，所以 **页内偏移占低 12 bit**

- 剩余高位：

  32−12=20 bit

  ，分成两级各 10bit：

  一级页目录号(10bit)+二级页表号(10bit)+不用查表页内偏移(12bit)

> 是不是需要一级页表 + 二级页表 两次查表，才能定位到物理页？
>
> ✅ **是，必须两次内存查表**：

1. 第一次：用「页目录号」查 **一级页目录** → 得到对应二级页表的物理基址
2. 第二次：用「页表号」查 **该二级页表** → 得到物理页框号
3. 最后：**物理页框号 + 页内偏移** → 唯一确定内存里那一字节

**如何优化文件传输**

本质是减少用户态与内核态的上下文切换和内存拷贝的次数，即减少系统调用次数，其实可以把read和write合并成一个sendfile

此外如何减少无意义的拷贝，对于文件传输这种场景其实数据不会在用户空间里再加工，所以用户缓冲区其实没有必要



如何实现零拷贝？

mmap（）系统调用函数：把内核缓冲区的数据映射到用户空间，使得OS内核与用户空间无数据拷贝，直接write到socket缓冲区



还有一种是直接sendfile，去替代read+write两个系统调用，直接把内核缓冲区里的数据拷贝到socket缓冲区，这种方式还减少了一次系统调用



并且如果网卡支持SG-DMA技术，可以让DMA把page cache里的数据直接写到网卡的缓冲区，这样减少一次内核态的拷贝，全程没有用CPU全是DMA控制器去做



事实上零拷贝在kafka、nginx都有应用





### IO多路复用

select：将已连接的socket放到FD集合，拷贝到内核，内核遍历检查到有网络事件产生标记可读/可写，再拷贝回用户态，用户态再遍历出来可读/可写

可见2次遍历+2次拷贝，且最多1024，而poll用链表替代数组，突破了数量限制，但二者时间复杂度都为On

并发数上来后性能较差





三者实现对比：

select和poll其实很像，只是poll改用链表实现，去掉了fd 1024的数量限制，用户程序需要全部遍历才能找到就绪事件，时间复杂度还是O（n）

而epoll重新设计：epoll_create创建epoll实例，epoll_ctl，epoll_wait

epoll内部用红黑树存所有注册的fd，然后有个就绪链表存有事件的fd，epoll_wait直接返回链表

fd注册后，内核在网卡驱动里挂回调函数，epoll有两种触发模式：

- 水平触发LT 默认，只要fd有数据没读完，每次epoll_wait都通知
- 边缘触发ET fd状态变化时只通知一次 必须一次把数据读完

一般LT比较通用，ET性能更高，减少通知次数，要求一次性读干净，nginx用的就是epoll ET模式















**处理器调度**

任务Task：线程、单线程进程

触发上下文切换：执行时间用尽/等待IO请求/睡眠/中断

调度决策：下一个执行的任务/执行该任务的cpu/执行时长



调度目标：

批处理系统：高吞吐量 即单位时间内处理的任务尽可能多

交互式系统：低响应时间

网络服务器：可扩展性

移动设备：低能耗

实时系统：实时性

高资源利用率/多任务公平性/低调度开销



**经典调度**

1、first come first served

平均响应时间/短任务不友好



2、shortest job first

调度不公平，任务饿死

响应时间过长，但周转时间短



3、抢占式调度

时间片：任务被调度一次后，可以执行的时间

通过定时触发的时钟中断来实现抢占式调度，而非执行至终止



时间片轮转算法：

公平，响应时间短，但牺牲了周转时间

特别是在任务耗时相同的场景下最明显，因为都要到最后才执行完



OS中任务优先级不同，需要区分使得关键任务及时执行，引入多级队列

高优先级任务先执行，同优先级内RR或FCFS



什么任务适合高优先级--IO绑定的任务，提高资源利用率，时延要求高，等待时间过长的任务

### **文件系统**

文件即一段有名字的字符序列，本身被称为文件数据，而字符序列的长度、创建时间、权限等等称为文件元数据

磁盘的最小读写单位是块block，每一块都有一个编号即块ID

如果数据结构来记录文件和多个块id的对应关系，即inode，index node

多层次的inode：

- 直接指针
- 间接指针
- 二级间接指针

有效减少inode大小，在磁盘头部专门存放inode，每个inode用数组索引来命名即inode号，可以把磁盘理解为很大的磁盘块数组



磁盘格式化即将磁盘划分成不同区域的过程，格式化后一部分磁盘区域被inode表等元数据占了，空间变少了



通过目录把字符串映射到inode号，文件系统目录记录了文件名到inode号之间的映射

### 内存管理

为了实现进程间的隔离，操作系统给每个进程发一套独立的虚拟地址，进程只跟虚拟地址打交道，至于虚拟地址最后落到哪块物理内存不关心，进程访问虚拟地址时，CPU里的内存管理单元MMU会根据映射关系翻译成物理地址，再去访问内存



- 进程隔离 每个进程一套页表
- 突破物理内存大小限制，程序运行有局部性，暂时不用的页可以先换到磁盘上，需要用时再换回
- 对进程来说是一片统一且连续的地址空间



虚拟地址到物理地址 如何映射

通常将虚拟地址空间和物理内存切成固定大小的块

页表存在内存里，每个进程有自己的页表，CPU里有个寄存器CR3，存着当前进程页表的物理地址



TLB：地址翻译的加速缓存，CPU内部的告诉缓存，存最近用过的页表项，这样不用每次都去内存里查

空间局部性原理



**缺页异常**

访问的虚拟页不在物理内存，触发缺页异常

1. cpu发现页表有效位=0 触发缺页中断
2. OS介入 从磁盘把对应数据加载到某个空闲页帧
3. 更新页表

如果物理内存满了，OS选一个页换出到磁盘，这就是换页即SWAP



**页换出策略**

1、未来最久不会被用到的页

这是最优的，但也是无法实现的，需要预知未来

2、LRU 最近最少使用

那就需要维护每个页上次访问的时间戳，精确实现代价高

Redis内存淘汰策略也是采用近似LRU

3、LFU

历史高频页难以换出

4、Clock算法 近似LRU

用一个访问位近似替代时间戳，每次访问某页自动把访问位置为1，OS定期把所有访问位清0

换出的时候，如果页访问位是1，置位0，继续遍历，如果页访问位是0则换出





**多级页表**

对单级页表来说，其实大部分虚拟地址空间根本没用到，但却依然在页表里填充



二级页表把虚拟地址拆成三段：页目录号+页表号+页内偏移

对于没有用到的虚拟地址范围，对应的页表就不分配



实际可能是用多级页表







### 零拷贝

数据从磁盘到网卡，不需要经过用户空间，内核直接搬运



linux2.1支持sendfile系统调用，直接在内核内部完成传输，用户态完全不参与

- 用户态调用sendfile 
- 数据从磁盘由DMA拷贝到内核缓冲区
- CPU拷贝 从 内核缓冲区到socket缓冲区
- DMA拷贝 从socket缓冲区到网卡

这样用户态代码完全不碰数据，只负责发起调用



如果网卡支持scatter-gather的话，直接把内核缓冲区的地址和长度告诉网卡，不需要CPU拷贝了

这样全程都是DMA拷贝 CPU不参与搬运 这就是零拷贝的由来



实际应用：kafka的consumer拉取消息的时候，用sendfile，数据直接从磁盘日志文件发到网卡，不走kafka进程，吞吐量很高，这种IO密集型场景例如kafka、nginx静态文件，吞吐提升很明显



还有另一种零拷贝：用户态直接IO，有些场景（数据库）不想经过内核缓冲区，直接绕过内核

比如mysql的数据页，自己在buffer pool维护了一套缓存，就走直接IO



**DMA**

专门负责搬运数据的硬件控制器，几乎所有IO设备都用DMA，磁盘控制器、网卡、声卡

本质是让宝贵的CPU资源从繁琐的数据搬运中解放出来，CPU只需下达指令，DMA去完成数据传输后中断通知CPU

### TCP/UDP

TCP是可靠、有序、面向连接的协议，发送前必须先通过三次握手建立连接，数据保证送达、顺序、不重复

UDP则是无连接、不可靠、快

TCP适合网页浏览、文件下载、邮件

UDP适合视频通话、在线游戏、DNS查询



**TCP如何保证可靠传输**

TCP通过序列号追踪每个字节，用ACK确认收到，用重传补救丢失，用窗口机制控制发送速度

1、确认应答ack

每一段数据发出去，接收方必须回一个ACK确认，其数字含义是期望下一个收到的序号，例如数据包1收到后回ack2

2、超时重传

发出去的包，如果超过一定时间没收到ack，就认为丢了重发

3、序列号+去查排序

TCP给每个字节都编了序号，接收方用序号重新排序乱序到达的包，并去掉重复的包

4、流量控制

防止发送方发太快，把接收方缓冲区撑爆，接收方在每个ack里携带窗口大小，告诉发送方我还能接收多少字节

当ACK window=0 发送方暂停发送

5、拥塞控制

感知网络状态，防止网络链路被压垮

刚建立连接时，发送量从小开始，指数增长，探测网络能承受多少，增长到一定程度后改线性增长

检测到丢包，认为网络拥塞，立刻大幅降低发送量，再慢慢涨



**三次握手与四次挥手**

握手：

1、客户端发送SYN给服务器 我想连接，初始序号x

2、服务器发SYN+ACK给客户端 ack是x+1 同意连接 序列号y

3、客户端 发ACK给服务器，ack为y+1 表明收到了你的y 可以开始传输



挥手：

1、主动关闭放 发送FIN seq=u

2、被动关闭放 发ACK=u+1 表明收到

3、等服务器把剩余数据处理完 也发一个fin给客户端

4、客户端回ACK 表明收到 此时进入TIME_WAIT 等待2MSL后进入CLOSED



握手的三次是通信双方都确认对方收到的最小次数

挥手需要四次 因为服务器收到客户端FIN 只能先回ACK 但此时可能还有数据没发完 不能马上FIN

TIME_WAIT是什么：为什么客户端要等2MSL

1. 最后一个ACK如果丢失 服务器会重发FIN 需要在线才能会ACK
2. 防止旧的连接延迟数据包影响新连接 等待旧的数据包都消失



TCP连接靠四元组区分：源IP/端口 目的IP/端口，

端口号是16位，允许的最大端口号是65535



### IP

internet protocol属于网络层协议，主要分IPV4和IPV6，主要作用是对数据包进行路由和寻址，使得它们能跨网络传输并正确到达

寻址：给每台设备分配唯一地址

路由：数据包在网络中一跳一跳转发，每个路由器决定下一跳发给谁



IPV4 即32位 写成四段四进制

192.168.1.100 实际是：11000000.10101000.00000001.01100

一共43亿个地址

地址分为网络部分（标识在哪个网络）和主机部分（网络里的第几台）

子网掩码决定边界在哪，例如255.255.255.0 前24位是网络 后8位是主机

IPV4的地址已经不够用了，现在靠NAT网络地址转换缓解：

家里多台设备共用一个公网IP

设备A 192.168.1.2  ─┐
设备B 192.168.1.3  ─┤── 路由器 ── 公网IP 1.2.3.4 ── 互联网
设备C 192.168.1.4  ─┘

192.168.x.x 是私有地址，只在局域网内有效，
路由器负责私有地址和公网地址直接转换



IP是无连接、不可靠的，可靠性由上层的TCP来保证，IP只管转发

每个路由器都有一张路由表，每一跳只知道下一步去哪

每个IP包都有TTL字段，每经过一个路由器-1，减到0就丢弃，防止数据包在网络里无限循环



特殊IP地址：127.0.0.1 本机回环地址localhost

0.0.0.0 所有地址或未知地址



**如何获取客户端真实IP？**

如果直接读取TCP连接的RemoteAddress，其实在有代理/负载均衡的架构下拿到的是代理服务器的IP，而非客户端真实IP，代理服务器会把真实IP放在请求头里透传，应用需要从请求头读取



关键请求头：X-forwarded-for

每经过一个代理，就在末尾追加该代理的IP，例如客户端

规则：取第一个非私有IP即为真实客户端IP

### 树

完全二叉树：除最后一层外，若其余层都是满的，并且最后一层是满的或是在右边缺少连续若干节点，则这个二叉树就是完全二叉树

这导致父节点和子节点的序号有对应关系，假设从1开始编号，那么假设父节点的编号是i，则左子节点的编号是2i，右子节点的编号是2i+1

这个性质使得完全二叉树可以利用数组存储，可以极大地节省空间，以及很方便地利用序号快速定位某个节点的父节点和子节点，当然普通二叉树也可以用数组存储，但存储利用率较低

AVL树，高度平衡的二叉搜索树，保证左右两颗子树的高度差绝对值不超过1



**遍历**

还有层序遍历 借用队列实现





### 堆

堆是满足以下条件的树：每一个节点值都大于等于或小于等于子树中所有节点的值，即大根堆和小根堆

一般用完全二叉树来实现，方便存储和索引



**重要操作**

1、插入元素

先将插入的元素放在最后，然后自底向上浮动



2、删除堆顶元素

删除完堆顶后，把末尾元素移到堆顶后，向下浮动

这样让它继续保持完全二叉树的结构，而不会出现空位



**应用-堆排序**

第一步是建堆

第二步是排序：将堆顶元素





### 跳表

跳表是一种基于有序链表的数据结构，底层仍然是一张完整的有序链表，即所有元素都会出现在最底层，在最底层

链表之上，再建立若干层更稀疏的索引

普通链表每次只能往后走一步，而跳表可以在高层索引中一次跳过多个节点

跳表的查找、插入、删除是Ologn操作



redis的zset为什么用skiplist



跳表是一种可以替代平衡树的数据结构，使用概率平衡而不是严格强制的平衡，因此跳表的插入和删除算法比平衡树的等效算法简单得多，速度也快



B+树的核心是通过可能少的IO操作去定位到更多的索引来查询数据，更适合作为数据库和文件系统常用的索引结构，而redis作为内存数据库不太需要，跳表实现更简单

### 红黑树

自平衡二叉搜索树，通过对节点染色来维持树的平衡，保证基本操作时间复杂度为Ologn

1. 每个节点是黑色或红色 根节点固定为黑色 所有叶节点为黑色
2. 红节点的两个子节点必须是黑色 保证没有连续的红节点
3. 从任意节点到其所有后代叶节点的路径上 黑色节点数量相同

插入/删除后通过旋转和重新染色回复这五条规则



### 图

图是一种较为复杂的数据结构

- 线性数据结构的元素满足唯一的线性关系
- 树形数据结构的元素之间有明显的层次关系

而图形结构的元素之间的关系是任意的

基本概念：

- 顶点 
- 边
- 度 一个顶点包含多少条边，在有向图中还分出度和入度

无向图和有向图（有些关系是双向的 有些是单向的）、无权图和有权图（有时候节点之间的关系有强弱 可以用权值表示）



**存储**

一般用邻接矩阵或邻接表实现，邻接矩阵相对会浪费空间一点，但简单直接，可以快速获取两个顶点之间的关系，一般用邻接矩阵表示



邻接矩阵是从节点的角度来表示图，有多少节点就申请多大的二维数组，这种在边少、节点多的情况下会导致申请过大的二维数组，造成空间浪费





**搜索**

广度优先（借助队列）、深度优先（借助栈）

连通图：任何两个节点都可以到达

强联通图：在有向图中任何两个节点都可以相互到达

### 双指针

双指针的核心思想是：用两个指针在数据结构上协同移动，将原本需要嵌套循环的O（n^2）的问题降至O（n）

两种主要形态：

1、对撞指针 (left/right 从两端向中间收拢)

适用于有序数组，利用单调性捡枝，



2、快慢指针（slow/fast）

同向 适用于链表或需要探测周期/位置的场景

slow：每次走一步

fast：每次走两步

或者是类似滑动窗口这种一个在前一个在后



使用双指针的前提是

- 有序性
- 问题可以用排除来缩小搜索空间

其实滑动窗口（两指针维护一个区间，right扩张，left收缩）

分离双指针（两个指针分别在不同数组上移动，如归并排序的合并阶段）







### 回溯算法

回溯的本质是穷举，穷举所有可能然后选出我们想要的答案，本质上这并不是很高效的算法，可以通过剪枝提高效率，因为有些问题能暴力搜索出来就不错了

组合与排列：组合不强调元素顺序 排列强调



回溯算法的要点：

- 确定返回值和参数 
- 终止条件
- 回溯搜索的遍历过程

```text
void backtracking(参数) {
    if (终止条件) {
        存放结果;
        return;
    }

    for (选择：本层集合中元素（树中节点孩子的数量就是集合的大小）) {
        处理节点;
        backtracking(路径，选择列表); // 递归
        回溯，撤销处理结果
    }
}
```

for循环是横向遍历，backTracking是纵向遍历，这样就把这棵树全遍历完了
