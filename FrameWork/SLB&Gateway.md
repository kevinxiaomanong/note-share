### **一、简介**

SLB是携程的软负载系统，主要提供HTTP协议请求的路由负载功能

核心功能还有拉入拉出服务器、缩容扩容、健康检测等



**三层路由**

请求通过DNS解析出来的IP，使用4层协议网络层到达硬件LB

根据到达的VIP通过4层协议将请求负载到SLB服务器

SLB根据七层协议HTTP中的信息，域名和访问的URI，将请求路由负载到具体的应用服务器



**SLB实现**

基于开源软件Nginx实现负载路由



### 二、核心概念

- SLB 代表一个具体的SLB实例，由一组具体的SLB服务器组成，携程由多个SLB实例提供服务
- VS 代表一个域名管理单元 可以有多个域名，但域名的职责功能配置绝对一致
- Group 一个应用在SLB上的投影，是SLB基本管理单元，大多数运维操作是针对Group的



**VS**

即virtual Server，是域名服务在SLB上的投影，定义了一组域名和一个端口





### 三、SLB的一些限制

最大请求体大小：30MB

超过之后直接以413返回 请求不转发到后端服务器

超时时间 120s 504 GateWay Timeout



### 四、软负载架构

三层分层：

1、GSLB 全局负载均衡

做地域调度 用户访问域名 分配最近的接入节点



2、边缘接入层

只做流量转发 不解析HTTP 四层LB



3、应用网关层 

用NGINX 解析HTTP 七层LB

### 五、Gateway延伸-Netty框架

如何让你去基于Netty实现一个网关你会怎么做？

无非是监听端口，作为网关入口，接收浏览器/客户端http请求，根据path/host去做路由规则

再把请求转发到对应的后端服务，然后把后端响应写回客户端，这是最精简的网关

真实生产级别会在此之上去加：异步转发（用netty异步客户端再发一次请求）然后过滤器链（鉴权 限流 灰度 日志）从注册中心获取服务列表动态路由、负载均衡，且网关到后端服务是有连接池的，避免频繁重连



### 六、与RPC对比

- SLB/Nginx 负责公网流量进门
- 微服务网关/Netty 负责微服务体系接入、统一管控
- RPC/SOA/Dubbo 微服务之间互相调用



RPC：远程过程调用框架

核心能力：服务注册发现、负载均衡、高效序列化、透明调用



proxygate是携程L7正向代理，这里要区分正向代理与反向代理，proxygate是携程内部系统对外部可访问域名做集中式管理以提供安全性，同时可以提供固定的出口IP减少网络策略的配置













### QA

1、GSLB怎么理解 为什么说它是智能DNS DNS不应该是共有的网络设施么？



是公司自己搭建、只负责自己域名的超级DNS

手机先访问www.trip.com问公共DNS，公共DNS只管指路，引到携程自己得DNS服务器，然后根据城市、运营商、负载去给一个最优接入点IP，GSLB不取代公共DNS而是在公共DNS后面做精准分配的那一层



2、四层LB原理

收到流量转发到七层LB集群

修改数据包的目标MAC地址，然后直接转发给下一台机器



3、七层LB

即申请的SLB 来根据规则转发



4、如何搭建自己的DNS服务器

首先买域名，你可以不用厂商的DNS服务器，用自己搭的DNS

去域名控制台把NS记录改成自己的DNS服务器

全球最标准的DNS服务器BIND，这样全世界访问你的域名都会去你的DNS查IP

你可以在你的 DNS 里写判断逻辑：

- 北京用户 → 返回北京服务器 IP
- 上海用户 → 返回上海服务器 IP
- 移动用户 → 移动线路 IP
- 电信用户 → 电信线路 IP
