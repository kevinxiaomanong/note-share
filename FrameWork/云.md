# 云计算

## Landing Zone 架构

### 是什么

Landing Zone 是企业上云时的**基础蓝图**，定义了一套标准化、安全、可治理的云环境初始框架。可以把它理解为"地基"——在任何业务系统迁移或部署到云之前，先把网络、权限、安全、合规、计费等基础设施统一规划好。

核心思想：**先治理，后建设**。避免各团队各自为政，导致环境混乱、安全漏洞和成本失控。

---

### 核心组成

| 模块 | 内容 |
|---|---|
| **组织结构** | 账号/订阅分层（按 BU、环境如 prod/dev/test 隔离），缩小故障爆炸半径 |
| **IAM 身份与权限** | SSO 单点登录、MFA、最小权限原则、RBAC 角色边界 |
| **网络架构** | Hub-Spoke 拓扑、VPC/VNet 隔离、CIDR 规划、防火墙、私有端点 |
| **策略即代码** | AWS SCP / Azure Policy / GCP Org Policy 强制加密、区域限制、合规基线 |
| **安全与合规** | 默认安全配置、专用安全订阅、职责分离、满足行业监管要求 |
| **可观测性** | 集中日志、链路追踪、告警、事件响应 |
| **成本治理** | 预算告警、异常检测、标签强制、分摊计费（Chargeback/Showback） |
| **自动化** | IaC（Terraform / Bicep / CloudFormation）模板，标准化交付流程 |

---

### 主要云厂商实现

**AWS**
- 以 AWS Organizations 为核心，多账号体系
- Service Control Policies（SCP）做统一策略管控
- Control Tower 提供开箱即用的 Landing Zone 框架

**Azure**
- 以订阅（Subscription）为核心管理单元
- 分为 Platform Landing Zone（共享服务：网络、日志、安全）和 Application Landing Zone（各业务负载）
- 八大设计域：账单与租户、IAM、资源组织、网络、安全、管理、治理、平台自动化
- 推荐使用 Azure Verified Modules（AVM）构建，模块化可插拔

**GCP**
- 以 Folder 和 Project 做层次隔离
- Org Policy 做约束控制

---

### 核心价值

- **一致性**：所有订阅/账号统一配置标准，避免"野生环境"
- **安全合规**：从第一天起内置安全基线，满足监管要求
- **可扩展**：新业务接入不需要重新设计基础设施，直接复用
- **降风险**：环境隔离缩小爆炸半径，集中可观测快速响应
- **成本可控**：标签+预算+告警，杜绝云账单失控

---

### 与普通云部署的区别

```
普通上云：业务先跑起来，治理后补 → 技术债堆积，安全风险暗藏
Landing Zone：治理先行，业务按规落地 → 规模化后管理成本低
```

---

### 适用场景

- 企业大规模云迁移启动前的基础建设
- 多团队/多业务线共用同一云账号体系
- 有合规监管要求（金融、医疗、政务等）
- 从单账号混用演进到多账号治理
