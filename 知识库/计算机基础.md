# 操作系统相关

## 磁盘

操作系统如何访问一个文件？过程经历了几次数据拷贝？从磁盘拷贝数据会占用CPU嘛？

访问过程：

1. 用户层调用 系统调用函数请求访问文件
2. OS解析，通过目录结构定位文件在磁盘的物理位置
3. OS将文件操作转换为磁盘具体指令，通过设备驱动程序发送给磁盘控制器
4. 磁盘控制器接收指令，控制磁头移动到目标位置，读取或写入数据到磁盘的物理扇区。



从磁盘读取数据到用户程序的内存空间，通常需要**3 次数据拷贝**：

1. **磁盘 → 磁盘控制器缓冲区**
   磁盘读取的数据首先存入磁盘自带的缓存（硬件缓冲区）。
2. **磁盘控制器缓冲区 → 内核缓冲区**
   数据从磁盘缓存拷贝到操作系统内核的页缓存（Page Cache）或缓冲区高速缓存（Buffer Cache）。
3. **内核缓冲区 → 用户程序缓冲区**
   数据从内核空间拷贝到用户进程的内存空间（用户态缓冲区）。



1. **数据传输阶段不占用 CPU**
   磁盘与内存的数据传输通过**DMA（直接内存访问）** 完成，DMA 控制器直接管理数据传输，无需 CPU 干预，此时 CPU 可处理其他任务。
2. **辅助操作占用 CPU**
   - 磁盘寻址、指令解析、文件系统权限检查等逻辑由 CPU 处理。
   - 数据从内核缓冲区拷贝到用户缓冲区时（第 3 次拷贝），需要 CPU 执行拷贝指令，会短暂占用 CPU 资源。



## IO

**标准IO（缓存IO）**

缓存IO又被称为标准IO，大多数文件系统的默认IO都是缓存IO，数据先从磁盘缓冲区复制到内核缓冲区，再从内核缓冲区到应用程序的内存空间

读操作：先检查内核缓冲区是否已经有数据，如果已经缓存了直接读取否则走磁盘读

写操作：将数据从用户空间复制到内核空间，这一步结束对于应用程序来说就是写完成了，至于什么时候将数据从内核缓冲区复制到磁盘，由操作系统决定，除非应用程序显式调用sync同步命令

在标准IO的机制中，通过DMA直接内存访问将数据从磁盘读到页缓存中，或是将数据从页缓存直接写回到磁盘，无需CPU干预，但数据从内核态到用户态的同步需要CPU执行数据拷贝指令，这会带来开销



**直接IO**

应用程序直接访问磁盘数据而不经过内核缓冲区，从而减少数据从内核缓冲区到用户态内存空间的拷贝操作

例如数据库管理系统这类应用往往有自己的缓存机制，例如Innodb缓存池，通常直接IO与异步IO结合使用避免阻塞等待



**内存映射**

Linux内核提供一种访问磁盘文件的特殊方式，它可以将内存中某块地址空间和我们要指定的磁盘文件相关联，从而把我们对这块内存的访问转换为对磁盘文件的访问，来减少数据在用户地址空间与内核地址空间的拷贝操作

本质是虚拟地址的共享映射，绝非用户态直接访问内核态



**网络IO与sendfile**

网络IO指应用程序与网络设备之间的数据传输过程，例如客户端发送文件给服务器，服务器返回数据给客户端

传统的网络IO以发送文件为例：

1. 磁盘-->内核缓冲区 DMA
2. 内核缓冲区-->用户缓冲区 CPU
3. 用户缓冲区-->内核socket缓冲区 CPU
4. 内核socet缓冲区-->网卡 DMA

可以看到存在CPU两次拷贝，且用户态与内核态的转换开销



零拷贝核心是减少数据在内核态缓冲区与用户态缓冲区之间的冗余拷贝，尽量让CPU脱离数据拷贝流程转由DMA处理。通过sendfile发送文件只需一次系统调用：

1. DMA copy将数据从磁盘读取到内核缓冲区
2. CPU copy将数据从内核缓冲区拷贝到socket缓冲区
3. DMA copy数据从socket缓冲区到网卡缓冲区

并且linux2.4内核还减少了从内核缓冲区拷贝到socket缓冲区这一冗余过程，让DMA自动从页缓存读取数据并写入网卡，这样CPU就完全不参与任何数据拷贝了，但这个仅支持文件到网络的单向传输，应用程序无法修改传输数据（不涉及用户态）很多高性能http server都引入了sendfile机制，例如Nginx
